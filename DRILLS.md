# Drills

Generated by `npm run drills:docs` from real runs on Node 22.22.0. Do not edit by hand: change the
code or the drill, then regenerate. Timings, ports and temporary paths (shown as `$TMPDIR`) vary between runs.
Terminal colour codes and Playwright's horizontal rules are removed; everything else is exactly what the commands print.

Each drill copies the repository to a scratch folder, runs the "before" command, makes one agent mistake (applies
the drill's patch, or runs a different script), runs the "after" command, and checks both exit codes and outputs
against `drill.json`. Your working tree is never changed. `npm run drills` runs all 26 and exits 0 only if
every one behaves as expected.

```text
# Incident log

One entry per agent mistake that got past you: into review, a
commit, or production. The first time is the model's; the
second time is a bug in your harness. Newest entry at the top.

A first miss fills steps 1 and 2: the fix goes in, and a guide
line under step 3 is optional. When the same root cause comes
back, complete the entry: a sensor that catches it (3), its
placement (4), a seeded-defect proof (5) and a retirement
condition. Mistakes you cannot afford even once (destructive or
irreversible actions, leaked secrets) get the complete entry at
once.

---

## YYYY-MM-DD: <the symptom, in one line>

**1. Symptom.** What you saw, where, and who saw it first. Link
the diff or log.

**2. Root cause.** Why the agent could do this. Keep asking
"why" until the answer is about your harness (missing context,
a wrong guide, no sensor), not about the model being careless.

**3. Control.** What stops it next time, and which kind it is:
guide (tells the agent before it acts) or sensor (catches the
result after); computational (a script decides) or inferential
(a model decides). Name the file.

**4. Placement.** Where the control runs: edit, commit, build,
deploy or live. Earlier is cheaper to fix; later sees more. Say
why you chose this one.

**5. Proof.** The seeded defect that shows the control works:
it passes without the mistake and fails with it. Give the
command and the output.

**Retire when.** The condition under which this control can be
deleted.

**Card.** The pattern card this became, if any (PNN).
```

**After**: `node drills/D02-incident-log/walkthrough.ts` (exit 0)

```text
## 2026-10-13: unit price 1.005 invoiced as 1.00

**1. Symptom.** After an agent change, the invoice form accepted
a unit price of 1.005 and stored it as 100 cents instead of
rejecting it. Found in review of a test invoice. The change in
app/src/http/invoice-routes.ts parsed the price with
parseFloat() and rounded (1.005 * 100 is 100.49999... in
floating point).

**2. Root cause.** Nothing told the agent that money is integer
cents. One unit test did fail (it expects a 400 for 12.345), but
the agent read it as an outdated test and changed it, because
nothing said why such prices are refused. Harness gap: no guide
in AGENTS.md, and the only sensor did not explain itself.

**3. Control.** Both kinds. Guide: a rule in AGENTS.md, "Money
is integer cents, never floats". Sensor (computational):
guards/no-float-money.ts, which flags parseFloat, toFixed,
decimal literals in money lines and REAL columns, and tells the
agent to use parseCents/formatCents/taxCents instead.

**4. Placement.** Edit and commit: it runs in about 0.1s, so it
runs in the pre-commit gate (guards/gate.ts) and can run after
every agent edit.

**5. Proof.** Seed the defect in a scratch copy and run the
guard:

  without the defect: exit 0
    no-float-money: ok (21 files scanned)
  with the defect (drills/D06-float-money/mistake.patch): exit 1
    no-float-money: FAILED, 1 problem

        money amount into a float.
          unitPriceCents: Math.round(parseFloat(price) * 100),
        Fix: money in Invoicer is integer cents. Parse text with
          parseCents(), format with formatCents() and compute
          tax with taxCents(), all in app/src/domain/money.ts.
          Do not round floats.

**Retire when.** Amounts are a branded Cents type that the
compiler enforces, and the guard has not fired for 90 days

itself is drill D06.
```

## Making your own drill

1. Make the mistake by hand in a scratch copy of the repository (a git checkout), then save it:
   `git diff > drills/DNN-slug/mistake.patch` (add new files with `git add -N` first so they appear in the diff).
2. Write `drills/DNN-slug/drill.json` with the guard command and the exit code and text you expect before and after.
3. Run `npm run drill DNN` until it behaves, then regenerate this file.
